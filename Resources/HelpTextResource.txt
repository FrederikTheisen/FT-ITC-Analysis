## About \appname
\appname is a desktop application for macOS, Windows, and Linux for processing, analyzing, designing, and presenting isothermal titration calorimetry (ITC) experiments. It is a standalone graphical application that can be installed and launched like other desktop programs. All core workflows are available through the interface; no programming or scripting is required.
# What you can do with it
**Work on your own computer:** process and analyze ITC data away from the instrument workstation, whether in the office, at home, or while traveling.
**Import data from multiple sources:** raw data from MicroCal-style instruments, exports from TA Instruments, PEAQ-ITC project files, integrated heats, and \appname project files.
**Process thermograms:** define baselines and integration regions using automated tools, with manual adjustment where needed.
**Design experiments:** simulate titration layouts, model parameters, injection volumes, small first injections, and tandem experiment designs before collecting data.
**Fit models:** perform single-experiment fitting or global analysis across multiple experiments, including optional temperature-dependent constraints where applicable.
**Review and export results:** inspect analysis results, derived thermodynamic values, advanced analyses, and export CSV/TSV result tables.
**Export figures:** generate publication-ready plots in the classical calorimetric style, with optional residual plots for diagnostics.

## Getting Started
# Loading Data
When the program opens, press **\enter** to browse for files or press **\space** to load the most recently used project or data file(s). After loading, inspect the dataset in the **Overview** tab.
The overview displays experiment metadata such as instrument information, experiment date and duration, cell and syringe concentrations. The experiment date/time, concentrations, temperature, comments, and other experiment attributes can be edited in the experiment details view. A changed date is marked as user-modified. On macOS, the details sheet has separate Details and Attributes tabs. Details groups experiment information, conditions, concentrations, and comments; Attributes contains optional metadata. Separate date and time controls include seconds. Use Add Attribute for a new row; each tab scrolls with Cancel and Apply available at the bottom.
# Compatible File Formats
\appname can read the following file types:
**MicroCal-style raw data:** `.itc`
If an `.itc` file contains multiple concatenated runs, the app asks whether to use the MicroCal concentration progression or enter back-mixing settings between segments.

**Origin ITC projects:** `.opj` (the first compatible ITC worksheet supplies the raw trace when available, or integrated heats otherwise; ResultsLog text is retained as provenance, but Origin fits and processing are not imported)
**TA Instruments NanoITC native data:** `.nitc`
**TA Instruments NanoAnalyze exports:** `.ta`
**PEAQ-ITC project files:** `.apj`
**Integrated heats:** `.dat`, `.aff`, `.dh`
The first integrated-heat injection is imported but excluded from fitting by default; you can include it manually, and it still contributes to later concentration bookkeeping. For `.dat` and `.aff`, **Recalculate concentrations and ratios** chooses whether to calculate the trajectory from the injection volumes or retain the table progression. The choice starts from Preferences and applies to this import batch. `.dh` has no stored concentration progression, so its concentrations are always calculated.
**\appname project files:** `.ftxtc`
**Legacy \appname projects:** `.ftitc` (read-only; save as `.ftxtc` to continue working)
Drag compatible files into the app window, or use **File > Open...** to select them manually.
Once loaded, datasets behave the same in the application regardless of instrument type. \appname does not modify raw data files. To make a project portable across computers, save it as a `.ftxtc` file.
Legacy `.ftitc` projects can be opened for migration, but the application no longer writes that deprecated format.
Drag a non-button area of any Data or Analysis Result row to reorder the data list. The chosen order is used throughout the application and is saved in `.ftxtc` projects.

## Processing Data
For raw thermograms, processing is the first step in ITC analysis. Integrated-heat imports skip this step. It consists of defining the baseline and the integration region for each injection.
Integrated heats are calculated by numerically integrating the baseline-corrected thermogram over the selected integration window. Power samples represent trailing-period averages, so partial intervals at selected boundaries are included using the right-endpoint sample. In the **Processing** view, you can zoom using the controls in the lower-left corner or by dragging a zoom region. To focus on a specific injection, double-click within its injection scope.
# Selecting a Baseline Type
\appname supports three baseline models.
**Spline baseline:** places baseline handle points around injection scopes and interpolates between them. The spline can be linear or smooth. Sparse, balanced, and dense point-density settings control the target number of points per injection, while the app adapts the actual point count to the usable baseline length. Handle values can be based on the mean or median of local baseline points. Spline points can be shown, moved, added, removed, or locked for manual correction.
**Polynomial baseline:** fits a single polynomial across the thermogram while iteratively rejecting outlier points such as injection peaks. This method offers less manual control but can perform well on low-noise thermograms. Lower degrees give a less flexible baseline and higher degrees give more flexibility but increase the risk of overfitting.
**Segmented baseline:** fits local constant, linear, or quadratic baseline segments before and after injection regions, then blends across the integrated peak windows. This mode is useful when the baseline drifts differently in different parts of the thermogram or when a single global polynomial is too rigid.
By default, baseline fitting excludes points inside the integration regions. As a result, changing integration start or end positions can also change the fitted baseline. Locking the processor freezes all processing results and disables graphical editing of integration regions and spline points. Lock individual spline points instead when you want to preserve selected points while continuing to process the experiment.
Polynomial and segmented baselines can be converted to spline baselines when you need manual point-level editing after an automatic fit.
# Injection Bookkeeping
**Discrete displacement** is the default and recommended starting point for ordinary pulse injections. It represents injection displacing the previous cell mixture before appreciable mixing, followed by mixing of the remaining material with the injected solution. **Ideal continuous mixing** assumes mixing throughout the injection, so the displaced solution changes composition continuously; consider it for slow injections or to compare the opposite mixing limit. **MicroCal** follows its documented displaced-volume convention, including the concentration approximation; use it to reproduce or compare MicroCal analyses. These methods determine concentrations and displaced binding heat used by fitting. Switching an existing experiment invalidates its fits but leaves measured heats and baselines unchanged.
Preferences > Processing > Injection bookkeeping selects the method for new data. Experiment Details can explicitly switch an ordinary experiment; doing so recalculates concentrations and invalidates its fits. Saved projects retain historical processing until explicitly changed, and older unknown methods display “Saved processing — unchanged”; choose a method before recalculating their concentrations. Name/comment edits do not change methods. Rebuild tandem experiments through the tandem tool to change bookkeeping.
For MicroCal, u is cumulative injected volume divided by active cell volume, including delivered injections excluded from fitting. Starting with no ligand in the cell, ligand concentration is Cs*u*(1-u/2), where Cs is syringe concentration; cell material is retained by (1-u/2)/(1+u/2). This uses the manual's approximate ligand expression, while its displacement assumptions remain approximate. Saved concentrations and fits remain unchanged until concentration reprocessing.

Ideal continuous mixing is an ideal-mixing approximation inspired by Philippe Dumas (2022), doi:10.1007/s00249-021-01588-4. It does not model imperfect mixing or kinetic single-injection analysis. No option is assumed to be empirically superior. Very large injections or sharp transitions can exceed the accuracy of its fixed integration rule.
Discrete displacement follows the convention described by Ernesto Freire, Arne Schön and Adrián Velazquez-Campoy (2009). It retains a fraction (1-v/V) of the previous cell mixture per shot and calculates q = Qend - (1-v/V)*Qstart, where Q is equilibrium cell binding heat content. The displaced-heat correction is therefore (v/V)*Qstart, using the pre-injection heat content. Each shot must satisfy 0 <= v < V; cumulative injected volume can exceed the cell volume. This convention is useful when comparing analyses that use the same bookkeeping, but FT-ITC and other programs may still differ in model calculations and offsets. It is not an imperfect-mixing correction or an empirically proven improvement over MicroCal.
# Setting the Integration Region
Choosing an appropriate integration region is important both for accuracy and for noise reduction. Integrating over the full injection scope often adds unnecessary noise.
\appname allows you to adjust all integration regions together using **Start** and **Length**. Both values are measured from the beginning of the injection: **Start** sets the start boundary, and **Length** sets the end boundary. For example, Start = 2 s and Length = 20 s give an 18 s integration region. Use **\peakfit** to estimate end points from the decay of the baseline-corrected response.
You can also edit injections individually by dragging the blue region markers. When zoomed to a single injection, pressing **\space** copies the current end-point offset to the next injection and advances the view. The start boundary is also copied when **Copy start time to next** is enabled.

## Analyzing Data
Preferences use the same built-in values in both desktop applications: the optimizer iteration limit starts at **20,000**, and automatic concentration SD starts at **10%**. **Restore Defaults** stages these values; **Apply** saves them, while **Cancel** leaves preferences unchanged. Saved custom values, including values outside the slider presets, remain in effect until changed. Choosing **Apply** preserves preferences that are not shown in that application's window.
Model fitting is performed in **Analyze Data**. \appname provides five fitting models:
**One-set-of-sites:** single binding process with one class of sites.
**Two-sets-of-sites:** two independent classes of binding sites fitted simultaneously.
**Sequential Binding Sites:** two, three, or four ordered binding steps, with a separate stepwise affinity and enthalpy for each step.
**Competitive binding:** titration of a target ligand into a macromolecule initially equilibrated with a competitor.
For Competitive Binding, **Ligand Affinity** and **Ligand Enthalpy** can each use **From attributes**. Add a **Competitor properties** experiment attribute and select a one-set-of-sites Analysis Result. Its global summary Kd and ∆H, including uncertainty, are copied to that experiment's model options when a fit starts. Temperature-dependent results are evaluated at the experiment temperature; otherwise the source summary temperature is used. The row shows source status; hover over the status or selector for the full result name and a short Kd and ∆H summary with units and SD. Missing sources retain captured values when available. Opening the editor only previews values; a fit refreshes the saved capture.
Model options can be edited before experiments are ready. With **From attributes** enabled, the next fit uses each experiment's attribute value in its model option; the entered value is used only after the toggle is turned off. Different experiments in a global fit can use different values. If an included experiment lacks a required attribute, fitting stops and one error dialog lists the affected experiments and attributes. A fit that cannot start keeps any previously attached solution. **Update Result** reads the current attributes again; saved results continue to evaluate with their stored model options.
**Dissociation:** dilution-driven monomer–dimer self-association, with macromolecule in the syringe and buffer initially in the cell.
Models use the included integrated heats from the selected experiment or, in multiple-experiment mode, the Active experiments.
# Single-Experiment Analysis
The default workflow is to analyze one experiment at a time. Select a model, set fitting options, provide reasonable initial parameter guesses, and run **\btnfit**. Injections can be excluded prior to fitting if needed.
# Syringe Correction Mode
In most ITC workflows, a fitted N-value is interpreted in the traditional MicroCal-style way and mainly compensates for uncertainty in the effective concentration of the species placed in the cell.
Syringe correction mode is intended for cases where the main uncertainty is instead in the concentration of the material loaded in the syringe. When this mode is enabled, the fitted stoichiometry term is interpreted as a correction of the syringe-side titrant concentration during fitting rather than as a correction of the cell-side concentration. The result table reports this term as α when syringe correction is active.
# \multexp and Global Fitting
You can analyze multiple experiments at the same time using **\multexp** mode. In this mode, all Active datasets are analyzed together. Enabling **Create analysis result** stores their fits in a combined Analysis Result. With no shared constraints, experiments are fitted independently; shared constraints connect them in a global fit.
Global fitting is useful for difficult interactions and for enforcing constraints across experiments, for example shared parameters across replicates, concentrations, or conditions. A typical workflow is to load and process the relevant experiments, mark the experiments you want to include, choose which parameters are shared or allowed to vary, and then run the fit.
If the experiments were performed at different temperatures, the analysis result can expose temperature-dependent values such as \dh°, \dg, \tds, \kd, and \dcp where applicable. Analysis results can also enable derived analyses based on temperature, buffer, or salt conditions.

## Analysis Results
A usable completed fit creates an **Analysis Result** in the data list when **Create analysis result** is enabled. Otherwise, a single-experiment fit remains attached to its Experiment Data. Opening a result shows the included experiments, solver information, unweighted RMSD, the optimizer objective when it was captured, weighted fitting state, uncertainty method, model options, constraints, and a table of fitted parameters. Repeated desktop validity reasons affecting more than two experiments are summarized by category with an affected/total count; smaller or unrecognized reasons remain detailed. The Information criteria summary shows one AICc or AIC value; hover its individual rows for the criterion, included-injection, and fitted-parameter explanations. When switching directly between analysis results, the selected experiment is retained when the destination contains the same experiment ID. Result-table columns size to their headers and displayed values within compact limits. Drag a header boundary to adjust a width; tables wider than the workspace scroll horizontally.
The viewer's saved result can report analysis warnings when a primary or uncertainty fit reached a parameter boundary, or uncertainty refits reached an optimizer limit; these warnings remain visible even when the validity snapshot is stale or unknown. In the viewer, RMSD is an unweighted display diagnostic in µJ, separate from the weighted fitting objective. A saved global convergence record may also provide a separate Molar RMSD value in kJ/mol; missing values stay unavailable and the result metric is not reconstructed by averaging member fits.

**AIC / AICc** includes one estimated residual-variance parameter in both weighting modes (K = fitted parameters + 1). Weighted criteria use injection integration errors as relative uncertainties and estimate one common variance multiplier from all included standardized residuals. This does not change the stored errors or fitted parameters. Analysis-level criteria pool the observations before estimating the variance; they are not sums of individual member criteria. Compare the same observations and likelihood convention. AICc uses the standard small-sample approximation for nonlinear fits and is unavailable when n ≤ K + 1. Scores are recalculated when projects are opened, so weighted scores from the former fixed-sigma calculation can change.

**Profile likelihood** estimates conditional confidence intervals at a fixed 95% level while retaining the primary best fit. A bound reached before the likelihood threshold is recorded as censoring, not as an endpoint. A complete interval requires threshold crossings on both sides of the best fit. Its `value ± SD` display uses an equivalent symmetric scale, not a sample standard deviation. Advanced analyses can sample the stored uncertainty summaries, but profiling creates no bootstrap ensemble. Saved leave-one-out refits can provide an envelope on the integrated-heats graph. Weighted profile intervals use processing-derived injection SDs as unchanged relative weights and estimate the overall residual scale separately with an F-calibrated threshold; fitting never writes that scale back to an injection SD. Legacy saved fixed-SD profiles remain identified by their stored calibration. Save the project as `.ftxtc` to preserve profile diagnostics and endpoints.
# Result Evaluation
The Correlation view uses complete residual-bootstrap refits to show Pearson correlations between fitted coordinates. Point to a cell to see Pearson r and an approximate 95% Monte Carlo precision interval; refit counts are listed once in the result panel. The panel also warns about coarse simulation precision, frequent failed refits, unresolved signs, excluded non-finite coordinates, and structurally rank-limited matrices. These diagnostics describe the finite bootstrap calculation; they are not parameter confidence intervals and do not establish model validity.
The result view evaluates thermodynamic quantities at a chosen temperature. When temperature dependence is fitted, the reference temperature is used by default; otherwise the mean experiment temperature is used. The result view can report \dh, \dg, \tds, \kd, \dcp, N-values, and parameters for every active site or sequential step supported by the selected model.
For locally fitted member parameters, summary values include individual parameter uncertainty. **Combined SD** is the square root of the between-experiment sample variance plus the mean individual variance; temperature trends use residual variance in place of sample variance. It describes combined spread, not the standard error of the mean, and observed spread may already contain fitting noise. **Approximate propagated interval** targets the average or evaluated trend: individual lower and upper 95% interval widths are propagated separately and combined with the observed-spread contribution. The best-fit central values remain unchanged, and asymmetric intervals can remain asymmetric. Exactly two observations at distinct temperatures propagate individual errors without estimating residual variance; additional observations, including replicates at those same temperatures, contribute residual spread. ΔCp propagates the corresponding slope uncertainty. These intervals do not have established 95% coverage, especially with few experiments, and covariance between experiments is omitted even for local parameters coupled through a global fit. Shared and temperature-constrained parameters retain their model-estimated uncertainty and CI95 meaning.
# Derived Analyses
For one-set-of-sites results, additional tabs appear when the loaded experiments contain the required variation and metadata:
**Temperature dependence:** available when the temperature span is large enough, with Spolar Record-style thermodynamic structuring analysis.
**Ionic-strength dependence:** available when salt metadata is present and ionic strength varies across experiments.
**Protonation analysis:** available when buffer metadata varies across experiments.
# Exporting Analysis Results
Use **Export result...** from the context menu or analysis result view to open the analysis result exporter. You can select one or more results, export one summary row per result or all replicate rows, choose inline values or separate value/uncertainty columns, and write CSV or TSV output. Exported uncertainty can be standard deviation, interval bounds, or both. Local summary rows use Combined SD and an Approximate propagated interval; individual and model-estimated intervals retain their CI95 meaning. The same configured table can also be copied to the clipboard.

## Presenting Data
\appname is designed to produce consistent, publication-oriented plots directly from raw data.
# Final Figure
The publication figure layout follows the classical ITC presentation style: a thermogram together with integrated heats, model overlay, and optional residuals.
**Include excluded points in automatic Y scaling** lets excluded injections affect the automatic integrated-heat and residual ranges for the current figure. Explicit axis limits still take precedence.
Figures are generated from the current processing state and analysis result. Changing baseline or integration settings updates the integrated heats. Rerun the fit before exporting a figure based on the changed data; processing edits do not automatically refit the model.
# Exporting Data
\appname includes export functions for processed results. Depending on the export tool, you can export integrated heats, associated uncertainties, raw power-vs-time traces, fitted parameters, analysis result tables, and publication-oriented figures.
Export data using **File > Export** in the menu bar, from relevant context menus, or from the analysis result exporter. Fitted parameters can also be copied from the analysis result view.

## Experiment Designer
The \designer supports planning ITC experiments from within \appname. It is intended for quickly checking experimental feasibility and setting up reasonable titration conditions before collecting data.
# What the Designer Simulates
The designer builds a synthetic experiment from the selected instrument, cell concentration, syringe concentration, injection count, injection volume mode, and optional small first injection. Injection volume can be calculated automatically from the instrument syringe volume or entered manually.
After a model is selected, the designer exposes the model parameters and model options used by the same fitting engine as the analysis workflow. The graph updates automatically when inputs change. Enable **Simulate noise** to add synthetic noise, then use the **Noise level** slider to scale it from 0.1× to 5.0×; 1.0× is the standard designer noise level. The designer can run a fit against the simulated data, which helps check whether a proposed experiment is likely to constrain the chosen model.
# Tandem Designs
The designer can simulate tandem experiments with multiple syringe loads. When tandem mode is enabled, the specified injection series is repeated for each segment and concentration bookkeeping is recalculated between segments using the tandem back-mixing model. Small first injections are applied at the start of each segment.

## Additional Tools
# Experiment Attributes
Experiment attributes are metadata attached to each dataset. They are used for derived analyses and for applying constraints in multi/global fitting. Attributes can be edited in the experiment details view and are stored in project files.
# Buffer Subtraction
Buffer subtraction is provided as a dedicated tool. Select a reference buffer experiment, select one or more target experiments, and apply the correction to the target experiments' integrated heats. The original integrated heats remain stored. Buffer subtraction operates on loaded data within the project and does not modify raw data files.
Three subtraction modes are available:
**Matched:** subtracts the matching buffer injection, with nearby valid injections used as fallback.
**Linear:** subtracts a straight-line fit through the included buffer injections.
**Exp. decay:** subtracts a single exponential decay fit through the included buffer injections.
# Tandem Experiment Concatenation
Tandem experiments can be collected by refilling the syringe while leaving the current cell content, producing multiple segments that should be treated as a single continuous titration. The tandem experiment merger combines selected loaded datasets into a single merged experiment.
The standard merge concatenates thermograms and recomputes injection concentrations and ratios across the combined titration. If an input experiment has already been baseline processed, the merger uses its baseline-corrected trace for that segment.
Back-mixing mode adds a simple overflow/dead-volume model between syringe loads. You can set the dead volume, choose whether displaced titrated solution was removed between segments, and adjust the fraction of the dead volume that mixes back into the active cell. The merged experiment stores segment start concentrations so processing, fitting, and project saving treat it as one tandem dataset.
Automatic back-mixing estimates a reload fraction for each selected source experiment. The estimate is model-based and can differ from the actual liquid mixing.
Tandem concatenated experiments retain fewer adjustable experiment parameters than normal experiments due to the calculations required to do the concatenation.
