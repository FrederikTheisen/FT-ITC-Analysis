FT-ITC Project Viewer data flow and retention

This page describes the browser-based FT-ITC Project Viewer.

Opening a project: opening a file uploads the entire selected .ftxtc project to app.ft-itc.org, including its embedded data and comments. The server returns parsed data to the browser and does not keep the parsed document as application session state. Upload buffering and expanded archive entries can use server temporary files. The archive reader attempts deletion when disposed, including normal error exits, but cleanup failures or process interruption can leave files behind. FTXTC parsing logs stages, counts, component IDs and recovery/error details; therefore the viewer is not log-free.

Retention and deletion: the viewer does not retain a server-side copy of the parsed project for later access; parsed data is returned to the active browser session. Temporary files used during upload and archive processing are cleaned up after the request as part of normal disposal. Cleanup is best effort, so an error or process interruption may leave temporary data behind. We do not claim a guaranteed deletion time for host or proxy logs, crash leftovers, disk snapshots, or backups. Closing the viewer cannot remove data already sent for that viewing request.

AI interpretation traceability: when an AI interpretation package includes experiment evidence, non-empty external experiment, cell sample and syringe sample identifiers entered in FT-ITC may be sent with that package. The package may also include a SHA-256 fingerprint of the ordered raw thermogram samples or, for integrated-only experiments, the injection volumes and raw integrated heats with their reported uncertainties. The fingerprint supports identifying reused source data; it does not encode sample names, filenames or processing choices.

Automated interpretation providers

Privacy notice update ft-itc-privacy-1.1. Automated interpretation sends the selected evidence and instructions to the provider selected in the desktop application: OpenAI or Mistral. This is separate from opening a project in the viewer.

OpenAI: existing API data controls apply. FT-ITC disables Responses API response storage. Provider retention and infrastructure records remain separate from local report storage.

Mistral: FT-ITC uses its EU regional chat-completions endpoint. Available models may include Z.ai GLM models hosted by Mistral. Regional inference controls inference location; it does not guarantee that all account, billing or operational metadata stays in that region. Training preferences and zero data retention are separate account controls. No zero-retention guarantee is made for this service.

See Mistral regional inference, retention controls, and training preferences. The selected provider's applicable terms and configured account controls govern its processing.
