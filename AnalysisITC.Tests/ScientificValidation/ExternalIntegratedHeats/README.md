# External software integrated-heat comparison

These synthetic injection heats are generated by **pytc 1.1.5**, using the
unmodified upstream implementation at commit
[`d9ccde3f04e35a3d821ff37a4ad42e62a048d4ac`](https://github.com/harmslab/pytc/tree/d9ccde3f04e35a3d821ff37a4ad42e62a048d4ac).
The generator calls pytc's `SingleSite`, `SingleSiteCompetitor`, and compiled
`BindingPolynomial` models. It does not call or copy FT-ITC's model equations.
There are seven native-protocol files and four injection-refinement companions.
See [RESULTS.md](RESULTS.md) for successful recoveries and the retained native
higher-step mismatches; [results.json](results.json) contains every fitted value.

The `.DH` files contain **absolute integrated injection heats in microcalories**,
not thermograms and not heat divided by injected amount. FT-ITC imports them
through `IntegratedHeatReader`. Select **microcalories** and **Exponential**
dilution when opening these files manually. The test checks that every imported
heat and injection volume matches the frozen reference. No baseline or peak
integration is run. Include the first injection: these ideal synthetic files
have no first-shot artifact.

This is a cross-software numerical comparison with known generating parameters.
It is synthetic evidence, not an experimental measurement or a study of
uncertainty calibration. Raw-thermogram references elsewhere in this folder
test processing and are not used as isolated model-verification evidence.

## Model and protocol definitions

All experiments use a 200 µL cell, 1 µL injections, 25 °C, zero dilution
background, and no added noise. `reference.json` records the complete protocol,
upstream parameters, mapped FT-ITC parameters, heat arrays, source hashes and
file hashes. Concentrations in this table are initial analytical concentrations.

| File | Cell / syringe concentration | Injections | Generating FT-ITC parameter equivalents |
| --- | --- | ---: | --- |
| `one-site-exothermic.DH` | 20 µM / 0.5 mM | 40 | N 1.1; log10 Ka 6.2; ΔH −32 kJ/mol |
| `one-site-endothermic.DH` | 40 µM / 2 mM | 40 | N 0.85; log10 Ka 5.2; ΔH +24 kJ/mol |
| `two-independent-sites.DH` | 20 µM / 2 mM | 60 | N 1 and 1; log10 Ka 6.4 and 5.0; ΔH −25 and +15 kJ/mol |
| `competitive.DH` | 20 µM / 0.5 mM | 40 | Target N 1.15, log10 Ka 7.0, ΔH −18 kJ/mol; competitor 30 µM total, log10 Ka 6.2, ΔH −8 kJ/mol |
| `sequential-2.DH` | 20 µM / 2 mM | 60 | Step log10 Ka 6.4, 5.7; step ΔH −30, +20 kJ/mol |
| `sequential-3.DH` | 20 µM / 2 mM | 60 | Add step log10 Ka 5.0 and ΔH −18 kJ/mol |
| `sequential-4.DH` | 20 µM / 2 mM | 60 | Add step log10 Ka 4.3 and ΔH +14 kJ/mol |
| `sequential-3-subshots-10.DH` / `sequential-3-subshots-100.DH` | 20 µM / 2 mM | 60 | Same three-step parameters; each injection sums 10 or 100 native pytc subshots |
| `sequential-4-subshots-10.DH` / `sequential-4-subshots-100.DH` | 20 µM / 2 mM | 60 | Same four-step parameters; each injection sums 10 or 100 native pytc subshots |

pytc's active-cell fraction maps to FT-ITC's ordinary N parameter in the
one-site and competitive cases. Syringe-activity mode is disabled.
Competitor concentration, affinity and enthalpy are supplied inputs, not target
fit parameters. The competitor concentration includes both bound and free
competitor before target titration.

pytc's binding polynomial uses cumulative Adair constants and **state**
enthalpies. For sequential steps, βᵢ = K₁ × … × Kᵢ, and the enthalpy of state i
is the sum of the first i step enthalpies. These parameter mappings occur
before calling pytc; generated heats are not adjusted afterward.
The explicitly named refinement files additionally sum upstream subshot heats,
as described below; no fitted or empirical correction is applied.

For two independent sites, with one site of each type, the polynomial is
`(1 + K1 L)(1 + K2 L)`. Its coefficients are `β1 = K1 + K2` and `β2 = K1 K2`;
the singly occupied state's enthalpy is `(K1 H1 + K2 H2)/(K1 + K2)`, and the
doubly occupied state's enthalpy is `H1 + H2`. This special integer-stoichiometry
case can therefore be generated by pytc and fitted with FT-ITC's two-class model.
It does not independently qualify arbitrary fractional two-class stoichiometries.

## Injection-convention difference

The upstream [`ITCModel._titrate_species`](https://github.com/harmslab/pytc/blob/d9ccde3f04e35a3d821ff37a4ad42e62a048d4ac/pytc/indiv_models/base.py)
uses the product of `1 − v/V` for retention after discrete injections. Its
heat calculation uses the post-injection active-cell concentration multiplied
by the change in mean bound-state enthalpy. FT-ITC's Exponential option uses
`exp(−Σv/V)` and a finite-injection correction to changes in cell heat content.
These are different approximations even though both start from integrated
heats. They are not made equal by renaming a dilution option.

The files preserve the external program's original heats and physical volumes.
This comparison uses a predeclared **2%** allowance and must not be described
as machine-precision equality of the forward models. There are 0.005 cell
volumes per shot and at most 0.3 cell volumes cumulatively in this reference.
Residual differences and parameter bias are recorded explicitly; a failure is
not resolved by replacing the external data with FT-ITC predictions.

The native three- and four-step fits exceeded the 2% parameter criterion. A
separate refinement study preserves those original files and divides each
1 µL injection into 10 or 100 successive upstream pytc deliveries. Only their
predicted heats are summed into the corresponding 1 µL output row. The
macromolecule/ligand concentrations, total delivered volume, generating
parameters, FT-ITC injection rows, fitting starts and acceptance are unchanged.
This changes the external forward simulation's injection discretization; it
does not involve power-curve processing or baseline integration. Recovery
improves markedly, supporting a discretization explanation for the original
discrepancy. FT-ITC still has its own finite-injection approximation, so the
refined comparison is not an exact equality test either.

## Acceptance and fitting settings

`ExternalIntegratedHeatReferenceTests` first evaluates FT-ITC at the generating
parameters, then fits each complete integrated-heat dataset with both
Levenberg–Marquardt and Nelder–Mead, from two declared starts. All applicable
N, affinity, enthalpy and offset parameters are free, including the sequential
offset. Equivalent complete site-label swaps are accepted for independent
sites; sequential step labels remain ordered.

Acceptance was specified before the first fit:

- Maximum absolute forward heat discrepancy ≤2% of the largest absolute
  injection heat. This denominator remains meaningful near a zero crossing.
- Each recovered N, Ka and ΔH within 2% of its generating value.
- Absolute recovered offset ≤50 J/mol (the generating value is zero).
- Successful solver termination; all numerical acceptance quantities finite.

The starts shift alternating log10 affinities by ±0.15, step/site enthalpies
by ∓15%, every fitted N by ±15%, and offset by ±100 J/mol. Both start directions
are used for every solver and dataset. There are 20,000 allowed iterations/
evaluations, optimizer-tolerance preference 1, and a Nelder–Mead tolerance
modifier of 1e−4. Uniform injection SD of 1e−10 J scales the objective without
changing its least-squares optimum. No uncertainty estimation is run. These
are numerical comparison settings, not a default-settings or broad-start
optimizer qualification.

The tests can write every forward/fit result to the directory named by
`FTITC_EXTERNAL_VALIDATION_RESULTS`, including generating-value discrepancies
before assertions. This allows failed recovery attempts to remain visible.
The eight native three-/four-step recovery attempts are explicit opt-in
diagnostics with the original strict acceptance. They are not counted as
successful validation. Normal regression runs execute all forward comparisons
and the other recovery cases, and show the diagnostic theory as skipped.

## Reproduction

Use Python 3.12 and an isolated environment. Install the versions in
`requirements.txt`, clone the source repository, and check out the commit above.
Then install that checkout without dependency resolution or build isolation:

```sh
python -m pip install -r requirements.txt
python -m pip install --no-deps --no-build-isolation /path/to/pytc
python generate_reference.py --pytc-source /path/to/pytc
```

The generator checks the Git revision, verifies tracked upstream files are
unchanged, and compares the installed model source files against the checkout.
It includes a Python 3.11+ compatibility alias from `inspect.getargspec` to
`inspect.getfullargspec`; pytc reads only their common `args` and `defaults`
fields. The numerical source and compiled binding-polynomial routines are
unchanged. A compiler and NumPy headers are required to build pytc's extension.

From the FT-ITC repository root, after normal .NET restore:

```sh
dotnet test AnalysisITC.Core.Tests/AnalysisITC.Core.Tests.csproj --configuration Release --no-restore --filter FullyQualifiedName~ExternalIntegratedHeatReferenceTests
```

To reproduce the complete study, including the eight known threshold misses,
set `FTITC_RUN_EXTERNAL_PROTOCOL_DIAGNOSTICS=1` and
`FTITC_EXTERNAL_VALIDATION_RESULTS` to an empty output directory before running
the same command. That strict study currently exits nonzero for the eight
documented native-protocol recovery misses. Then run:

```sh
python summarize_results.py --results /path/to/the/output/directory
```

The summarizer requires all eleven forward results and all 44 fit attempts,
including both starts for both solvers. It rejects incomplete reports.

Ordinary .NET test runs use the frozen fixtures and do not require Python,
pytc, a compiler for its extension, or network access.
